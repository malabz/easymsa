# Viewer 大数据性能优化：本地验收

日期：2026-11-10。仅修改本地独立分支 `codex/viewer-performance-20261110`，未推送 GitHub、未部署正式站点。

## 改动范围

- 网站任务结果新增有 token 和结果阶段鉴权的 FASTA 文件流接口。直接发送现有文件；已有且未过时的 gzip 可以复用，不临时生成压缩包。原 JSON 接口保留，新前端遇到旧服务缺少路由时回退。
- 文件、粘贴和任务结果共用 Worker 解析流程。文件按 1 MiB 读取，规范化、序列类型和 SHA-256 指纹在 Worker 中处理。解析后的 Worker 留给统计、搜索、区间计算、缩略图和导出，省去向第二个 Worker 再发送完整序列。
- 列计数和基础行计数合并为一趟遍历，使用字符编码查表；随后计算共识及参考比较。列结果先返回，行比较完成后再更新。改参考时复用列计数和基础行统计。
- 矩阵使用有 32 MiB 预算的绘图块缓存，选区及搜索命中单独绘制。淘汰、换文件、改变显示设置和卸载时释放画布缓冲；参考坐标映射复用，列显示元数据最多保留 64 块。
- 非等长文件保留原有缺失区域纹理绘制顺序，避免分块边缘裁掉斜线。统计、序列输出和图片导出仍使用原有全量数据及科学口径。
- 加载可取消并报告阶段；过期、权限、格式、超时和网络失败保留各自错误。失败或取消后，迟到的进度不能覆盖当前界面。

## 基准方法

旧版前端固定为 `e08316e`，旧版后端为 `682b8b0`。前端比较使用生产构建，同一台 Ryzen 9 7940HX / 31.2 GiB 机器、同一个 Playwright Chromium 构建，1440 × 900 视口。

四种规模分别为 500 × 10,000、5,000 × 10,000、50,000 × 1,000、500 × 100,000。每种同时测文件和网站结果入口，各预热一次、正式运行三次。固定种子 17 的生成器逐行生成独立序列，包含差异、N 和缺口；文件提前生成并复用，准备文件的时间不计入打开耗时。文件通过路径交给浏览器，不在测试调用中传入一个 50 MB 的内存 Buffer。

首次操作从选文件／点击 Alignment 前的标记开始，到浏览器实际处理 ArrowRight 并产生 `aria-activedescendant` 为止，包含自动化输入调用及页面事件处理；最终候选记录另保存 `automationMs`，不把它冒充纯解析耗时。首次显示、输入处理、列阶段和行比较的 Performance marks 均保留在原始 JSON 中。

“列及行统计”指 analysis Worker 请求发出至主线程收到并验证完整列／行结果，含共识、参考比较及结果消息传送，不含解析和图像导出。缩略图另有 Worker 开始／结束标记。首轮滚动从可以操作时立即开始，可能跨过统计完成时刻；随后再记录统计完成后的连续 180 帧。每次取帧间隔 P95，再比较三次 P95 的中位数。

网站入口使用本机只读 HTTP 服务提供固定的 FASTA 和旧 JSON 文件，经过真实页面、fetch、Worker 和 Canvas。它隔离了公网传输、线上并发及旧后端计算摘要的耗时；**网站入口的比例不能直接当作生产环境端到端提速**。后端鉴权、阶段选择、gzip 和历史文件通过独立 API/HTTP 测试核验。

内存采样与计时分开，使用 CDP 同时读取页面和所属 Worker 的 `Runtime.getHeapUsage`。分别保留 JS 堆、embedder 堆、ArrayBuffer／外部字符串 backing storage；合计按同一时刻计算，不相加各进程不同时刻的最大值。这不等同于整个浏览器的 RSS 或 GPU 进程内存。

## 原始记录与复现

- `baseline.json`：优化前四组规模、两种入口、一次预热和三次正式运行。
- `candidate-round1.json`、`memory-round1.json`：第一轮候选的记录，保留以便追溯。
- `candidate.json`、`comparison.json`、`measurements.md`：最终候选及自动生成的对比。
- `scripts/viewer-performance.mjs` 负责造数、入口操作、滚动和测量；`scripts/viewer-memory-lifecycle.mjs` 负责重复打开／关闭；`scripts/viewer-visual-parity.mjs` 比较冻结旧版与新版实际画面。

在 frontend 目录执行（Node 24.21+，先安装项目依赖和 Playwright 浏览器）：

```powershell
$env:EASYMSA_BASE_PATH = '/'
$env:VITE_API_BASE_URL = '/api'
node node_modules/vite/bin/vite.js build --outDir dist-performance
node scripts/viewer-performance.mjs --dist dist-performance --runs 3 --output docs/performance/viewer-2026-11-10/candidate.json
node scripts/summarize-viewer-performance.mjs
```

旧版构建使用完全相同的参数，放在独立目录，传给 `--dist`。计时期间不并行运行其他浏览器或测试。`--memory` 做独立内存采样；`--cpu-throttle 4 --viewport 390x844` 是模拟受限 CPU／手机视口的记录，不代表真实手机硬件。

差分验证使用 `src/features/msa-viewer/__reference__` 中冻结的旧算法，100 组固定种子样本逐项精确比较，包括 DNA/RNA、IUPAC、全缺口、共识平票和外部参考；另测未知字符、非等长、空数据、标题及行标识、跨块 UTF-8、原始／规范化指纹和 Worker 缓冲转移。

## 性能结果

最终前端源码为 `be40ac8`（此前的加载、统计、绘制提交均包含在内），后端为 `afbf0af`。后续提交仅保存测试脚本和验收记录。第一轮与最终测量的进程执行环境不同，因此重新在同一普通本机进程环境测了旧版和最终候选；第一轮数据保留为 `baseline-round1.json` / `candidate-round1.json`，不与最终数据混算。

[八组完整对照](./measurements.md)和[机器可读结果](./comparison.json)列出所有正式测量。5,000 条 × 10,000 列的三次中位数如下：

| 指标 | 本地文件：旧 → 新 | 网站结果：旧 → 新 |
|---|---:|---:|
| 首次可操作 | 2.95 → 1.90 秒（缩短 35.5%） | 4.24 → 2.25 秒（缩短 46.9%） |
| 完整列及行统计 | 12.05 → 1.90 秒（缩短 84.2%） | 12.21 → 2.09 秒（缩短 82.9%） |
| 首轮滚动 P95 | 21.0 → 28.8 毫秒 | 21.7 → 26.8 毫秒 |
| 统计完成后滚动 P95 | 28.9 → 27.6 毫秒 | 30.3 → 26.5 毫秒 |

三种 5,000 万格形状、两种入口的首次可操作耗时均缩短 **33.3%–46.9%**，完整列／行统计均缩短 **81.1%–84.6%**。500 万格常规数据的首次操作和统计也没有变慢。

**25 毫秒滚动目标未达到。** 新版在首轮滚动窗口内已完成并显示统计轨道，旧版在这一窗口内仍在计算；首轮 P95 实测更高，不能宣称滚动全面变快。统计完成后的滚动有小幅改善，仍超过目标。

最终候选的 5,000 × 10,000 分阶段数据如下。流式读取与解析重叠，不能拆成两个不重叠的耗时；“准备显示”还包含描述信息、序列类型处理和将显示数据交给主线程。

| 阶段（三次中位数） | 本地文件 | 网站结果 |
|---|---:|---:|
| 读取、解析及增量指纹至准备阶段 | 0.805 秒 | 0.513 秒 |
| 准备显示、交给主线程 | 0.662 秒 | 0.638 秒 |
| 列统计可用（从统计开始） | 0.769 秒 | 0.738 秒 |
| 随后的行比较 | 1.134 秒 | 1.343 秒 |
| 缩略图请求至完成（含调度等待） | 4.434 秒 | 4.699 秒 |

另有一次操作验收（非重复性能基准）：5 万条序列的搜索、筛选、末行跳转和名称排序均通过；10 万列可以在统计期间跳到第 99,999 列，选择最后两列并导出全部 500 条序列。导出文本与原文件相应区间逐行完全一致。[旧版记录](./interactions-baseline.json)、[新版记录](./interactions-candidate.json)。排序这一次为旧版 260 毫秒、新版 274 毫秒，不作为排序加速的证据。

## 内存与受限环境

50M 数据的独立内存采样同时覆盖主线程及全部 Worker。以下各列分别取同一时刻合计的峰值，单位 MiB；各列峰值发生时间不同，不能再把这一行的三个峰值相加当作总峰值。

| 入口／版本 | 已用 JS 堆 | ArrayBuffer 与外部字符串 backing storage | embedder GC 堆 |
|---|---:|---:|---:|
| 本地文件／旧版 | 170.3 | 144.1 | 165.2 |
| 本地文件／新版 | 171.9 | 60.4 | 212.6 |
| 网站结果／旧版 | 201.2 | 52.1 | 145.8 |
| 网站结果／新版 | 166.3 | 37.3 | 148.6 |

本地文件的外部缓冲减少，JS 堆峰值基本不变，embedder 峰值增加。网站结果的 JS 堆及外部缓冲减少。这是一次独立采样，不代表整个浏览器 RSS 或 GPU 的完整测量，也不能据此宣称所有内存类别都下降。[旧版采样](./memory-baseline.json)、[新版采样](./memory-candidate.json)。

连续打开 8 份标题不同的 50M 文件并关闭，8 个关闭检查点的 Worker 都为 **0**。统计缓存达到既有的 6 份上限后，关闭状态的主线程 JS 堆为 **73.81、73.84、73.88 MiB**，未继续按数据大小累积。打开状态保留一个计算 Worker；每次文件打开的 Worker 创建次数由旧版两次改为一次。[生命周期原始记录](./memory-lifecycle.json)。

采样脚本曾漏记一个检查点，之后又遇到 CDP 暂时列出已无法读取堆的、正在销毁的目标。最终脚本同步等待采样，并要求关闭后在 2 秒内完成 Worker 目标销毁，再取关闭状态。两次原始失败记录仍保留，没有把空采样或无法读取的 Worker 当作释放成功。

缓存预算分别为：已有主线程分析缓存最多 6 份／48 MiB，Worker 基础统计缓存最多 3 份／48 MiB，矩阵绘图块 32 MiB。当前数据、显示画布和临时计算空间另计，这些预算不是整个 Viewer 的总内存上限。

390 × 844、CDP 4× CPU 降速的单次正式记录中，本地／网站首次操作为 **2.06／2.58 秒**，统计完成后滚动 P95 为 **55.8／61.1 毫秒**，首轮为 **65.9／70.3 毫秒**。这是浏览器模拟，未覆盖真实手机硬件，不能套用桌面 25 毫秒目标或据此宣称低端手机已经流畅。[模拟记录](./mobile-emulated.json)。

## 正确性与浏览器检查

- 前端全量单元测试：**946 / 946**。最后的缺失区纹理及错误分类修正定向测试 **35 / 35**，其中包含一项新增的错误分类测试。首次与构建并行运行时，另一个提交页用例曾触发原有 5 秒超时；独立运行全量通过，未改用例或超时。
- 后端 API、结果服务及实际 HTTP 测试：**33 / 33**。覆盖 token、未完成任务、结果阶段、文件缺失、gzip 接受条件、旧 gzip 过期，以及只有原始 FASTA 的历史结果。没有重新比对历史任务。
- Chromium 核心 **22 / 22**；Firefox 核心 **22 / 22**。包含数据替换、搜索、参考比较、选区、恢复、导出和网络／鉴权路径。
- 三个浏览器并发运行核心测试，合计 **63 / 66**，3 项超时均发生在 WebKit；随后单独串行 WebKit 为 **21 / 22**。旧接口回退用例仍有间歇性超时。补全测试响应的跨域头后，三种传输情形各重复三次，合计 **8 / 9**，回退用例仍为 **2 / 3**，不能归为已修复。失败时曾停在 `calculating`，也观察到本地脚本／请求明显延迟；根因未确定。
- 手机／平板布局、触屏和无障碍：**16 通过、1 按原条件跳过**。包含 390、768、1280px；1440px 另由核心流程和新旧画面对照覆盖。移动 WebKit 的触屏操作通过。
- 未更新任何既有截图基准。原有 3 个截图用例在冻结的旧版也失败，主要是页面高度差异。以相同已加载字体直接比较旧版与新版，390／768／1280／1440px 共 20 组画面中 **19 组逐像素一致**；390px 概览的缩放图标有 **26 像素颜色差异**，其余区域一致。严格零差异脚本保留失败状态，没有提高阈值。[逐像素记录](./visual-parity.json)。

因此，本轮已具备可体验的本地实现，加载和统计的两个性能目标已达到；**滚动目标、WebKit 回退测试的稳定性及既有截图基准检查尚未全部通过**。
